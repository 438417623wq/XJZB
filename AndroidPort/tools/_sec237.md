## 八之三十七、v2.37:安卓网络层(socket 壳)+ 集成 bug 修复

`net/` 四个类落地:真 TCP/UDP socket 壳。**关键性质:`net/` 不 import
任何 Android 类型**(只有 `java.net` + `core`),所以**出货的那条路径
可以在桌面无头跑通**——真 `ServerSocket`、真 `Socket`、真握手、
真对局。`GameDesktop` 新增 `[v237]` 段 1 项(5 个子断言),
全量 **105 项 PASS**(连跑四次稳定)。

### 新增 `net/`

| 类 | 职责 |
|---|---|
| `TcpLink` | 实现 `core.LockstepLink.Link`。**读线程与主循环分离**——主循环若自己阻塞读,socket 上会死锁(进程内假链路测不出这种死法);`setTcpNoDelay(true)`,40ms 的 Nagle 延迟在 33ms 一回合上就是多等一回合 |
| `LanDiscovery` | UDP 广播收发。**广播而非组播**:手机对手机常在热点/廉价路由上,不需要支持组播的 AP |
| `LanHost` | 绑定(端口 0 由系统选)→ 组信标 → accept → **先握手后给座位** |
| `LanJoin` | 连接 → 交换握手 → 返回 `TcpLink` 或一句可读的拒绝原因;全程工作线程,不冻 UI |

### 抓到的集成 bug:`recordOrder` 的命令根本没上线

`Game.recordOrder()` 是**直接**把命令交给 session 的(`Lockstep.submit`),
而 `LockstepPeer.sendFrame()` 原来只发自己 `queue()` 的待发命令——
于是**命令在本地生效、永远不发给对手**:一次"带延迟的 desync",
而且**之前所有断言都看不见**(单机测试里两端本来就是同一个进程)。
修法:`Lockstep.submitted(player)` 暴露本回合该玩家已提交的内容,
`sendFrame()` 优先发它。`[v237]` 的 `orderCrossed` 断言就是钉这条的:
主机用 `recordOrder` 下令,客机必须收到**同一条**命令。

### 另外两处
