## 八之三十三、v2.33:局域网发现 + 大厅状态机

协议层最后一块可无头验证的东西:**怎么找到对方**(发现)和
**什么时候可以开局**(大厅)。做完这期,剩下的就只有 socket 壳与 UI。
`GameDesktop` 新增 `[v233]` 段 1 项(9 个子断言),全量 **102 项 PASS**。

### 新增

- `core/LanBeacon.java`:主机周期性广播一行文本,和指令流**同一套
  行分帧**(复用不是为了省事:抓包时发现流量和指令流读法一致,
  信标也能像回放一样被 diff)。过滤规则是**忽略而不是报错**——
  广播网段上会有别人的房、旧版本的房、以及无关 UDP 流量,
  一个遇错就抛的监听器会在同事手机连上 wifi 时把大厅打挂;
- `core/Lobby.java`:槽位 + 状态机。规则:`canStart()` 要求
  **全员已连接 + 全员已准备 + 至少 2 人**;`start()` **只能成功一次**
  (连点两下"开始"不能开出两局);**开局前**掉线要**清槽**
  (否则界面显示 4/4 而房主永远开不了局),**开局后**掉线大厅不管
  ——那是 `Lockstep` 的"等慢机"负责的,而且它是**可见的**
  (两台一起卡在同一回合),不是静默换人。

### `[v233]` 断言(9 条子断言)

1. 信标往返逐字段一致,且信标的字段直接构成 `Handshake`;
2. **8 种垃圾输入**(null / 空 / 无标签 / 缺字段 / 错版本标签 /
   缺 host / 数字非数字)全部返回 null **不抛异常**;
3. 别的版本的房**看得见但不可加入**;
4. 入座填最小空位;
5. **掉线释放的座位会被下一个人补上**;
6. 开局门禁:有人没准备 → false;全员准备 → true;不足 2 人 → false;
   并且 `blockedReason()` 说得出原因;
7. `start()` 第二次返回 false;
8. 开局后掉线**不再清槽**;
9. 大厅产出的数字喂 `Handshake`,两边互不拒绝(与 v2.32 接上)。
