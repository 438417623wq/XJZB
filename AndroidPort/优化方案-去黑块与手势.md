# AndroidPort 界面优化方案（v2.6 提案 · 仅方案不改代码）

项目：`F:\KF\XJZB\AndroidPort`（Android 原生 Java 移植，核心 UI 全在
`app\app\src\main\java\com\xjzb\rts\GameView.java`，2387 行）
目标：① 去掉底部小地图与九宫格之间的大黑块，多显示战场画面；② 顶栏大黑块改透明，只保留物资/时间文字；③ 手势改为"上下左右滑动=拖动视野、短按=框选/点选"。
本文件只做方案记录，不修改任何代码。

### 2. 手势现状（`onTouchEvent()` `GameView.java:1701-1848`）

- **单指滑动 = 框选**：`GameView.java:1777`
  `if (!boxing && Math.hypot(ev.getX()-downX, ev.getY()-downY) > 18 …) boxing = true;`
  位移超 18px 直接进框选——**没有单指拖动视野的路径**，这就是"点在屏幕上就是框选、上下拖动不顺畅"的根因。
- 短按（位移 ≤18px）在 ACTION_UP 走 `doTap()`；双击窗口 320ms/40px。
- 双指：拖动平移+捏合缩放（:1762-1773，`camX -= (cx-last2X)/zoom`）。
- 小地图上按下 = panning 平移镜头（:1741-1744）。
- 空框兜底平移：`doBoxSelect()` :2205-2206，框内选不中任何单位时才把框位移当镜头平移——所以滑动拖镜头"能用但不跟手"，且必然画出蓝框。
- 阈值 18px 硬编码两处：:1777、:1829。
- 边缘滚动 `edgeScroll()` :2162-2177：手指停在屏幕边缘 46*uiScale 带内镜头自动滚动，速度 460*dt。
- 命中区 `inHud()` :1857-1875：`y >= H-consoleH()` 整条控制台算 HUD；无选中时只有小地图带/命令卡带/编队槽算 HUD，其余穿透到地图。

## 二、优化方案

### 方案 A：底部大黑块去除（显示更多画面）

**A1. 控制台底板通栏 → 三个模块各自小底板（核心改动）**
- `drawConsolePanel()` :1155：删除/跳过 `c.drawRect(0,by,W,H,p)` 通栏不透明底。
- 小地图、信息面板（或编队槽条）、命令卡三块各自用 `bevelPanelTranslucent()` 自画半透明背板（α≈150-170，文字仍清晰），模块之间的空隙直接透出战场。
- 命令卡格子已有自身底色，命令卡区加一层 `PANEL_DARK_TRANS` 整体背板即可，无需通栏。
- 视觉收益：底部控制台中间与上方整片透出战场；等效于画面多显示约 `dp(150)` 高的一条，且不缩小任何控件。

**A2. 可选进阶：控制台半透明化而非"挖空"**
若希望保留一条完整控制带的轮廓感，把通栏底改成 `PANEL_DARK_TRANS`（argb 170 级）而非不透明 `PANEL_DARK`，一行改动：`GameView.java:1155` 的颜色常量替换。战场隐约可见，控件对比度不丢。
- 建议先做 A1（挖空），观感不满意再退 A2。

**A3. 空隙判定细节**
- `consoleH()` 与各模块矩形（minimapRect/infoPanelRect/cardRect）几何不动，只动填充，故 `inHud()` 命中判定、`drawMinimap` 视口框、命令卡按钮命中全部无需改动。
- 黑块挖空后，无选中状态下中间只有编队 1/2/3 三个小槽（`drawFormationOnly` :1208-1231），注意给这三个槽保留 `bevelPanelTranslucent` 背板（已有，:1214）。

### 方案 B：顶栏改透明（只显示物资/时间）

- `drawTopBar()` :1019-1020：删除 `c.drawRect(0,0,W,hud,p)` 通栏填充（或改为 `PANEL_DARK_TRANS` α≈60-80 的极淡衬底）。
- 文字可读性保障：资源/时间文字已带黑描边（`drawRes()` :1093-1098 先黑偏移再彩色），去掉底板后依然清晰；必要时把描边偏移从 1px 加到 2px。
- 暂停键 `bevelPanel(6,5,bs,bs)` 有自身底板，保留。
- "我方 N 敌方 N"计分文字同样描边绘制；若顶栏去底后与战场亮色冲突，可只在其后垫一块小尺寸 `PANEL_DARK_TRANS` 圆角条（局部，不通栏）。

### 方案 C：手势优化（滑动拖视野、短按框选）

现状是"位移>18px 即框选"，要改为"位移>阈值即平移镜头、原地短按才是点选、框选走长按"。具体：

**C1. 单指滑动 → 平移镜头（新增路径，核心改动）**
- 在 ACTION_MOVE（:1774-1793 的 else-if 分支）里，把现有 boxing 触发改成 panning：
  - `if (!panning && dist > 10px) { panning = true; }`（阈值 10px，比 18 更灵敏，起步跟手）
  - panning 时沿用双指分支已有的写法：`camX -= (ev.getX()-lastX)/zoom; camY -= (ev.getY()-lastY)/zoom;`（:1787 附近已有单指版代码，只是被 boxing 挡住）。
  - 每步更新 `lastX/lastY`，`clampCamera()`（:475）收尾。
- 消除起步迟滞的关键：定形为 panning 的那一步，把从 downX/downY 到当前的总位移一次性补进镜头：
  `camX -= (ev.getX()-downX)/zoom; camY -= (ev.getY()-downY)/zoom;` 之后才改为逐帧增量。这样 10px 阈值内被吃掉的位移立刻补回，上下左右拖动零迟滞。

**C2. 短按 = 点选（保留 doTap）**
- ACTION_UP 时若 `!panning && 位移 ≤ 10px` 走现有 `doTap()`（:1829 的 18px 阈值同步改成 10，与 C1 一致）。双击逻辑不变。

**C3. 框选改为"长按后拖动"**
- 单指按下后**停住约 250ms 不动**（借用 `touchDownAt` :1728 与渲染线程每帧检查，或在 ACTION_MOVE 里判 `System.currentTimeMillis()-touchDownAt > 250 && dist ≤ 10px`）→ 进入 boxing，随后移动扩大选择框；松手 `doBoxSelect()`（:2179-2215 逻辑全保留）。
- 进入框选瞬间给反馈：在按下点画一个短扩散圆环（参考渲染循环现有画圈方式即可），提示"已进入框选模式"。
- 框选期间不平移镜头；未进入框选的移动一律按 C1 平移。
- `doBoxSelect()` 里 :2205-2206 的"空框平移"兜底可保留（此时框选已不可能与平移混淆），也可移除，建议移除以免长按空框时镜头突跳。

**C4. 阈值与参数汇总（建议值，实施时可调）**

| 参数 | 现值 | 建议值 | 位置 |
|---|---|---|---|
| 滑动定形阈值 | 18px（进框选） | 10px（进平移） | :1777 |
| 短按判定 | ≤18px | ≤10px | :1829 |
| 长按进框选 | 无（滑动即框选） | 250ms 原地不动 | 新增，用 touchDownAt |
| 双指平移/捏合 | 已有 | 不变 | :1762-1773 |
| 边缘滚动 | 46*uiScale 带、460*dt | 不变（与单指平移天然兼容） | :2162-2177 |

**C5. 命中区/小地图兼容**
- 小地图按下平移（:1741-1744）不变。
- `inHud()` 无选中时的穿透区（:1858-1873）与新 panning 天然兼容：穿透区滑动就是拖镜头。
- `edgeScroll()` :2163 的 `!multiTouch` 条件保留；panning 与 edgeScroll 同时生效不冲突（一个手指拖、镜头到边缘再滚，体感顺滑）。

## 三、实施顺序与风险

1. **B（顶栏透明）** — 最小改动，2 行，先验证文字可读性。
2. **A1（底部挖空）** — 中等改动，只动绘制不动命中，风险低。
3. **C1+C2+C3（手势）** — 逻辑改动最大的一块，建议独立成一批，装到手机实测"上滑/下滑/左滑/右滑跟手度、短按选中、长按框选"三件事，特别是 C1 的起步补位移是否消除了迟滞。

风险点：
- C3 长按判帧要挂在渲染循环或 ACTION_MOVE 双通道，避免手指完全不动时收不到 MOVE 事件导致长按永不触发（可在 render/tick 里查 `touching && !panning && !boxing && now-touchDownAt>250` 补触发）。
- A1 挖空后小地图/命令卡的边缘轮廓用 `PANEL_EDGE_TRANS` 描边保持可辨识，否则透明底上控件边界发糊。
- 顶栏去底后战场亮色地图（如 volcanis）上资源文字对比度下降，靠描边解决；不足再加局部小衬底。
