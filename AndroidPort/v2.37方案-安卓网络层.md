## 设计要点

### `net/` 不 import 任何 Android 类型

这是本期最重要的一个决定。`net/` 只用 `java.net` + `core`,
于是**出货的那条路径可以在桌面无头跑通**:真 `ServerSocket`、
真 `Socket`、真握手、真对局。跑不了的只剩"点按钮"那部分,
而按钮后面没有逻辑。

| 类 | 职责 |
|---|---|
| `TcpLink` | 实现 `core.LockstepLink.Link`。**读线程与主循环分离** |
| `LanDiscovery` | UDP 广播收发 |
| `LanHost` | 绑定(端口 0 由系统选)→ 组信标 → accept → **先握手后给座位** |
| `LanJoin` | 连接 → 交换握手 → 返回 `TcpLink` 或一句可读的拒绝原因 |
| `NetSession` | Socket 进不了 `Intent`,单槽静态把会话从大厅交给对局 |

### 两个刻意的选择

1. **读线程与主循环分离**:主循环若自己阻塞读,socket 上会**死锁**
   (双方都在等对方先动)。进程内假链路**测不出**这种死法;
2. **广播而非组播**:手机对手机常在热点/廉价路由上,不需要支持
   组播的 AP。同时发 `255.255.255.255` 与**子网定向广播**
   (后者在部分安卓栈上才收得到)。

### 先握手后给座位

版本不符的对手**不能占座位**,否则房间显示满员而开始按钮永远点不亮。
拒绝消息**点名是哪一项**("地图不一致:divide vs hunters"),
"连不上"对玩家没有信息量。

## 本轮抓到的集成 bug

**`recordOrder` 的命令根本没上线**。`Game.recordOrder()` 是**直接**
把命令交给 session 的(`Lockstep.submit`),而
`LockstepPeer.sendFrame()` 原来只发自己 `queue()` 的待发命令——
于是命令**在本地生效、永远不发给对手**:一次"带延迟的 desync",
而且**之前所有断言都看不见**(单机测试里两端本来就是同一个进程)。

修法:`Lockstep.submitted(player)` 暴露本回合该玩家已提交的内容,
`sendFrame()` 优先发它。

另外:`LanHost` 必须**自己占 0 号座位**(房主也是玩家),
`BuildConfig` 打开(版本字符串只在一处定义,握手从它读)。
