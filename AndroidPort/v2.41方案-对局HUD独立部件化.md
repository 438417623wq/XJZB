# v2.41 方案:对局 HUD 独立部件化——撤掉上下两条透明带,战场全屏

> 前置状态:v2.39 已出包。玩家反馈:屏幕上下各有一大块"透明的板块窗口",
> 要求去掉;信息显示要各自独立成 UI——**时间是单独 UI、九宫格是单独 UI、
> 小地图是单独 UI**,不要这两整块透明视图。
> 本文排在 v2.40(联机语义特征化)之后执行,不动其编号。

---

## 一、这两块"透明视图"到底是什么(全部证据行号,GameView.java)

v2.23 把顶栏/底台的半透明压暗层(scrim)删掉之后,屏幕上下各剩下一条
**"无背景、只有一条 1px 分隔线"的常驻带**。它们不是新画的控件,而是
v2.6 以来"顶栏带 + 底台带"这条**布局模型**留下的骨架:

| # | 元件 | 现状 | 行号 |
|---|---|---|---|
| 1 | 顶栏带 | 高 40dp(`topBarH()`),整条带无背景透出地图,底缘一条 hairline | 1980-1982, 2498-2499 |
| 2 | 底台带 | 高约 150dp+(`consoleH()`),同样无背景,顶缘一条 hairline | 2007-2009, 2621-2622 |
| 3 | 带内浮件 | 顶:暂停芯片+描边字(资源/时钟/计数);底:小地图槽/信息面板/九宫格 | 2502-2552, 2627-2664 |
| 4 | 相机锚定 | 画面中心锚在两带之间的 playfield(`hud.centerY`),带里透出的地形只是"背景" | 991-996; HudLayout.java:141-144 |
| 5 | 手势死区A | `inHud()` 把 `y >= consoleTop` 与 `y < topBarH()` 整条划为 HUD | 4188-4210 |
| 6 | 手势死区B | 拖动/框选移动被 `getY() < getHeight() - consoleH()` 挡在底台之上 | 4031 |
| 7 | 边缘滚动 | 上下滚动限位按带算(`topBarH()+band` / `H-consoleH()-band`) | 5156-5157 |
| 8 | 带高依赖杂项 | toast y、任务消息 y、回放横幅 y、任务目标 y | 2094, 2359, 2073, 2340 |

它被读成"两个透明板块窗口"的三个原因:
① 两条 hairline 像窗框;② 相机把带里的地形当背景——点它不出兵、框选无效,
"看得见摸不着"正是一个"窗口"的手感;③ 手势层把两带整块划成死区。

**结论:根因不在"画了透明层"(v2.23 已经删了),而在"带"这个布局模型本身。
v2.23 只是把带涂透明,带还占着布局、相机与手势。要撤掉的是带。**

## 二、目标形态(设计基调一句话)

**屏幕 = 全屏战场 + 六个独立不透明部件;部件之间没有任何带、线、垫层,
部件之外的每一像素都是活战场(可点兵、可拖动、可框选)。**

六个部件,每个 = 自己的矩形 + 自己的绘制 + 自己的命中,互不隶属:

| 部件 | 内容 | 外观来源 |
|---|---|---|
| 时间芯片 | 时钟 mm:ss(小屏时"我方/敌方"计数并入) | **新增**:bevelPanel 不透明金属底 |
| 资源芯片 | 晶体 / 瓦斯 / 人口 | **新增**:bevelPanel 不透明金属底 |
| 暂停芯片 | 菜单按钮 | 已是,保留 |
| 小地图 | bevelSlot + 地图 | 已是,保留 |
| 信息面板 | 选中单位头像/血条;空选时只剩编队芯片 | 已是,保留 |
| 九宫格 | 命令卡 3×3 | 已是(v2.23 batch B 一块面板),保留 |

正是玩家点名的形态:**时间是单独 UI、九宫格是单独 UI、地图(战场)是单独
一整屏**。这与 v2.23"要么不透明要么全透明"的立场是同一条路走到头:
连"透明带"也不保留。

## 三、批次A:拆带(布局 / 相机 / 手势全屏化)

1. **HudLayout 去带化**:`compute()` 不再输出 `consoleTop`,`centerY = H/2`、
   `halfH = (H/2)/zoom`;`topH/bottomH` 参数降级为"贴顶/贴底部件的默认
   摆位参考",不再是禁区;新增 `clockRect`、`resRect` 两个输出矩形;
   `consoleHeight()` 退役(九宫格/小地图各自用自身高度,互不撑拽);
2. **相机全屏**:`render()` 的 `anchorY` 改为 `H/2`(991-996),上下钳制
   天然覆盖全屏——不再有"带里是背景"这回事;
3. **`inHud()` 重写**(4188-4210):由"按 y 判带"改为"点在六个部件矩形内
   之一";部件之间的缝隙一律返回 false(战场);
4. **手势死区B 移除**(4031):`getHeight() - consoleH()` 判断改为
   `!inHud(...)`——从缝隙发起的拖动/框选一路保持,手指滑进部件矩形时
   暂停、滑出继续;
5. **边缘滚动**(5156-5157):删掉按带计算的上下限位,全屏四沿滚动,
   部件上的手指由 `inHud()` 现有 guard 挡住;
6. 布局编辑器、框选绘制随之解除带限制(全屏可框)。

## 四、批次B:部件化绘制(两条新芯片)

1. `drawTopBar` 拆成 `drawPauseChip` / `drawResChip` / `drawClockChip`
   三个独立部件,各画各的 bevelPanel 不透明金属底 + 原描边字:
   - 暂停芯片:左上,不变;
   - 资源芯片:暂停芯片右侧,晶体/瓦斯/人口三个数值,人口超载时整块
     描红边(沿用现有变红规则);
   - 时间芯片:顶中,mm:ss;"我方 x 敌方 y"在窄屏时并入芯片第二行,
     宽屏时作为芯片右半区,不再单独飘字;
2. `drawConsolePanel` 更名 `drawBottomWidgets`:只画小地图 / 信息面板 /
   九宫格三块独立部件,hairline 删除;三块之间的缝隙全部归还战场;
3. 默认预设摆位:顶行=暂停(左)、资源(中左)、时钟(中);底行=小地图(左)、
   信息(中)、九宫格(右)——三块各自贴底,高度互不牵制;紧凑预设沿用
   "小地图浮顶左";镜像预设左右互换;
4. 九宫格 / 信息面板 / 小地图的绘制代码**零改动**(它们已经是不透明部件)。

## 五、批次C:编辑器扩展 + 杂项重锚 + 断言

1. **布局编辑器 3→5 面板**:spec 从 9 floats 扩到 15
   (cx, cy, size × 5,P_CLOCK=3、P_RES=4 加入);旧 9-float 存档
   迁移——前三面板原样保留,时钟/资源芯片落默认位;
2. **杂项重锚**(全部脱离带高):
   - toast:y = 底排最高部件 top − 芯片高 − 6dp(无底排时贴屏底);
   - 任务消息:同上锚点向上叠;
   - 回放横幅:时钟芯片 bottom + 6dp;
   - 任务目标:资源芯片 bottom + 12dp(顶左,避让三块顶芯片);
3. **`[v241]` GameDesktop 断言**:
   - 三预设 + 自定义 compute():无 `consoleTop` 输出、`centerY=H/2`、
     六部件矩形两两不重叠、全部完整落在屏内;
   - `inHud()`:任取两部件之间缝隙的点返回 false;旧带内但部件外的点
     返回 false;六部件矩形内的点全部返回 true;
   - 相机钳制按全屏半高(地图南缘可拖到屏底);
   - 常驻绘制序列无全宽矩形 fill、无 hairline(模态层除外)——
     v2.23 该断言的延伸;
4. **HudPreview 全量刷新**:新增"六部件"默认/紧凑/自定义三态截图 +
   一张"缝隙=战场"标注图(在两部件间隙画可点区域示意)。

## 不做清单

- 不做部件换肤 / 主题色;
- 不把时间/资源塞回底台合并显示(玩家点名要"单独 UI");
- 不做部件透明度可调(违反"要么不透明要么全透明"铁律);
- **不做**"全屏后底部单位被部件遮住"的补偿开关(这是 MOBA 惯例代价;
  若真机实测影响操作,再立后续版本做"双击小地图临时隐匿部件");
- 不动联机/锁步代码(本方案纯客户端表现层)。

## 执行顺序与门禁

```
门禁   = GameDesktop 全绿(含 [v241] 新增)
       → HudPreview 三态刷新 + 缝隙标注图
       → APK 素材比对 diff=0
       → 真机:部件间缝隙点兵/框选/拖动可穿、六部件点击正常、
         地图南缘可拖到屏底、四沿无黑边
v2.41 = 批次A(拆带)→ 批次B(两芯片)→ 批次C(编辑器+重锚+断言)
        ——三批同包发版;A 是几何/手势,B/C 是绘制与存档,互不耦合
```

铁律不变:**先证据后代码、GameDesktop 断言逐条加(本轮 `[v241]`)、
HudPreview 全分辨率刷新、APK 素材比对 diff=0、每批 APK 真机过一遍并记录。**
