## 二、剧情线（批次八：轻量任务引擎 + 人族迷你战役）

**原则：不做原版 TRIG 触发器字节码解释器**（工作量失控）。做**数据驱动的
脚本化任务系统**，Java 核心内实现、桌面可测——与项目"核心无 android 依赖、
GameDesktop 可回归"的既有文化一致。

### 8.1 任务脚本格式（assets/missions/mXX.json）
```json
{
  "map": "hunters", "playerRace": "terran", "enemyRace": "zerg",
  "difficulty": 1,
  "briefing": ["…简报字幕，逐条显示…"],
  "startUnits": [ {"type":"cc","x":..,"y":..,"team":0}, … ],
  "objectives": [
    {"kind":"destroyAll","desc":"歼灭全部虫族势力"},
    {"kind":"protect","target":"cc","desc":"指挥中心不能被摧毁"}
  ],
  "events": [
    {"at":{"time":120}, "action":"wave","units":["zergling"x8],"from":[..],"to":[..]},
    {"at":{"area":[x,y,r],"side":"player"}, "action":"reinforce", …},
    {"at":{"lost":"barracks"}, "action":"message","text":"…"}
  ],
  "aiPlan": {"waves":[…], "defenders":…}
}
```
- 核心新增 `Game.Mission`（解析 + 每帧 `updateMission(dt)` 检查 objectives/events，
  事件只支持 5 种原子动作：刷兵 wave / 增援 reinforce / 字幕 message /
  胜利 win / 失败 lose），~250 行，无 Android 依赖
- GameView 加简报覆盖层（title.webp 做底 + 字幕逐条 + 点击继续）与
  任务目标角标（顶栏下方一列 ✓/✗）
- 多目标并存时"主目标"失败才 lose，"可选目标"只影响结算评价（S/A/B/C）

### 8.2 迷你战役（5 关，复用现有 9 张地图）
| 关 | 地图 | 目标设计 | 教学点 |
|---|---|---|---|
| 1 | divide(小分界) | 守住基地 8 分钟，波次递增 | 基础运营、编队 |
| 2 | bottleneck(瓶颈) | 歼灭敌方前哨 | A 移动、坦克架塔 |
| 3 | boxer(拳王) | 限时救援友军据点 | 机动、巡逻 |
| 4 | darkcrystal | 夺取矿区并守住（protect+destroy 双目标） | 扩张 |
| 5 | hunters | 全图歼灭（敌方 AI 波次最强） | 毕业考 |
- 每关 events 写地形对应的伏击/增援，字幕讲一段自写的人族支线剧情
  （原版战役语音不在包内，不硬凑配音；用字幕 + 现有电台哔声）
- 战役进度存 `SharedPreferences`（通关解锁下一关 + 星级）

### 8.3 结算联动
- 批次七的 ScorePd 结算面板接任务数据：主/可选目标达成情况、S 评级条件
  （无主目标损失/耗时阈值）

### 8.4 验收
- `GameDesktop` 新增 mission 回归：m1 挂机 8 分钟判负、m2 歼灭判胜、
  protect 目标被拆判负、事件波次按时刻刷出——四条断言
- 真机：简报→战斗→结算全流程，进度解锁重进保留

## 三、战斗线（批次九：科技树 + 升级 + 新单位）

### 9.1 科技树收紧（把 `requires` 用满，不改结构）
现状 `requires` 只有一层（firebat→barracks 等）。补齐：
- academy（学院，150矿）新建筑 → firebat 改 requires=academy；
  解锁"兴奋剂"技能（HP -10，攻速 ×1.5 持续 8s，冷却 15s，实现为 Ent 计时器）
- engineering bay（工程湾）→ 攻/防升级各 3 级（矿 100/150/200，
  每级 dmg +2 / armor +1），命令卡在选中该建筑时显示升级按钮（带进度）
- ghost / wraith 类单位**本轮不做**（sprites 是否可解未验证，避免 v2.2
  "猜索引"教训——先逐帧渲染 cmdicons 与 GRP 核对再立项）

### 9.2 护甲与伤害类型（简版）
- `Type` 加 `armor` 字段（默认 0）；`damage()` 结算 `max(1, dmg - armor)`
  （保持"至少 1 点"防死锁）
- 不做原版 Small/Medium/Large 三类伤害全表——收益低、平衡成本高，
  只加护甲一维即可拉开"狗咬坦克没伤害、坦克咬狗一刀斩"的梯度

### 9.3 虫族 AI 强化（为战役服务）
- 波次组成按战役关卡配置（8.1 的 aiPlan），不再纯随机加权：
  前期狗海 → 中期刺蛇 → 后期混编飞龙
- AI 也吃护甲/升级（敌方升级取固定档位随难度）
- 进攻前 20s 播"虫群接近"警报（复用受击电台哔声，低频触发）

### 9.4 虫族可玩（可选，独立小批）
- 若战役后有余力：选族菜单（MainActivity 难度旁加族选）、
  overlord 人口（over_b.webp 已在 assets）、雄蜂建造逻辑复用 SCV 状态机、
  孵化场刷幼虫（数量上限 3）。**creep 蔓延不做**（迷雾/地形耦合大，性价比低）

### 9.5 验收
- 桌面断言：护甲减免数值正确（5dmg 打 2armor 剩 3）、兴奋剂攻速窗口、
  升级三级扣款与递增费用、academy 未建时 firebat 训练被拒（红条文案）
- 战役 m2/m5 用新 AI 波次重跑回归
- 平衡性走查：m5 毕业考用 3 档难度各通一遍（桌面模拟代替手玩）

## 四、批次顺序与理由

| 顺序 | 批次 | 理由 |
|---|---|---|
| 1 | 批次七 UI | 结算/设置是真机反馈的直接入口，且为剧情的结算联动打底；工作量最小 |
| 2 | 批次八 剧情 | 任务引擎是"游戏性"的最大增量，核心层可桌面回归，风险可控 |
| 3 | 批次九 战斗 | 科技/护甲改变数值平衡，放在战役之后让关卡配置直接受益 |
| — | 真机验证债 | v2.6 手势跟手度、批次六巡逻/修理/编队长按仍未真机验证——**随批次七一起还** |

## 五、主要风险
- **ScorePd PCX 调色板**：glue 下 PCX 可能是 256 色外挂调色板（同 v2.2 标题画的坑），
  先渲染单张验证再批量
- **任务引擎的胜利判定与 `status` 字段耦合**（`Game.java:1012-1020` 的拆光判胜
  必须在有关卡时让位给 objectives，`update()` 里要加 mission 判定分支）
- **命令卡格子紧张**：升级按钮 + 兴奋剂会让建筑卡超 9 格，复用批次六分页机制
  （`cardPage` 已有）
- 事件刷兵要用 `passMini` 校验落点（批次六教训：spawn 进墙里寻路返回空）
