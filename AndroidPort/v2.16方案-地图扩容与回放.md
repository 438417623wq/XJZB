## 批次三:地图扩容(153 张存量变现,P0)

### 1. 入库门禁:连通性自动检查(新增,先于选图)

- `pipeline_maps` 新增:**从每个出生点 BFS 可走图**,出生点两两连通才算
  "陆战可玩";不连通的(岛图)自动剔除并打印清单。
- 理由:游戏没有运输机登陆机制,`Island Hop / Sapphire Isles / Primeval
  Isles / River Lethe` 这类岛图选进来就是死局——这条检查必须在人工挑图
  **之前**跑,把 153 张先筛成"可玩池"。
- 顺带打印每张图的 出生点数/矿点数/瓦片集,作为挑选依据。

### 2. 精选 30 张入库(三组)

| 组 | 数量 | 候选 |
|---|---|---|
| 天梯经典 | 8 | Lost Temple / Dire Straits / Rivalry / Ashrigo / Polaris Prime / Acropolis / Proving Grounds / (连通性过滤后补位) |
| BW 瓦片集展示 | 10 | 冰原:Frozen Sea(陆块验证后)/ Hypothermia / Thin Ice;沙漠:Scorched Earth / Sirocco / Wasteland;暮光:Nightfall / Sanctuary / Azure Plains / Close Encounters |
| 休闲遭遇战 | 12 | 多矿大图优先(现游戏没有 6 矿以上图):Broken Steppes / Theatre of War / Tribes / Jungle Rumble / Killing Fields / Plains of Snow '98 / River Runs Through It / King of the Hill / StarCraft Fortress / Zergling Round-Up 等,按连通性结果定 |

- `maps/index.txt` 加分组字段:`id|名称|w|h|组`,组 ∈ skirmish/ladder/fun;
- `MainActivity` 遭遇战页签内加**分组吸顶行**(不做第三层页签,沿用
  战役/遭遇战框架,列表头插"天梯经典/休闲"分隔行即可);
- 大图硬指标:256×256 图 walk 数组 1M 布尔、地形块 256 块——LRU 上限 24
  不变,构建时间与低端机内存用 HudPreview/GameDesktop 量一遍;
- **验收**:30 张全部生成、每张开局跑 60 秒桌面模拟不崩、胜负判定正常、
  分组显示正确、APK 素材比对 diff=0。

### 3. 体积对冲:有损 webp 评估(与扩容同批)

- 30 张图入包后 APK 预计 +70~80MB(≈120MB 总量),超出合理范围;
- 现有 hunters 试验残留(q75/q80/q85/w80/w90)说明压缩阶梯已试过——
  正式化:**地形块用有损 webp q80, minimap 保持无损**,预计地图体积
  降 3~5 倍;
- 验收:同一张图无损/有损并排渲染对照(桌面帧),肉眼不可辨再全量切;
  slim_assets 加 `--terrain-quality` 参数,保留无损开关。

## 批次四:回放系统(小批,技术杠杆最大)

- 前提已满足:核心确定性(`Random(12345)` 固定种子)、update 固定 1/30
  步进、无系统时钟依赖(时钟是累积 dt);
- **录制**:`game.post` 指令队列的每条指令带 tick 号,追加进
  `replayLog`;结算页加"保存回放"(复用存档对话框);
- **格式**:头部 = 地图 id / 难度 / 种子 / 版本号 + 指令流
  (tick,action,args…),纯文本行,复用存读档的解析风格;
- **播放**:主菜单加"回放"入口(复用存档列表 UI),从 0 重演对局,
  tick 到达时注入指令;播放中禁止输入,ESC/返回键退出;
- **验收(桌面)**:录 180 秒含移动/建造/开火的对局 → 重放 →
  逐秒实体状态哈希与原局一致;中途存档-读档-继续录的混合场景可延后;
- 这一步同时是路线图 P3(WiFi 直连对战)的指令同步地基。
