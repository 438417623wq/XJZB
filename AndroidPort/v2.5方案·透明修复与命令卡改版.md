## 一、"透明"的根因:地面阴影污染了 Paint 的 alpha

### 1.1 定位过程

- 先查素材:把 `cc_b / marine_b / barracks_b / scv_b` 的 alpha 通道做直方图,
  **全部只有 0 和 255 两档**,没有任何半透明像素 → 素材没问题。
- 再查渲染路径:`grep setAlpha|setStyle` 发现 `p`(共享 Paint)在十几处被改,
  逐处核对都在用完即恢复。
- 最后用桌面复现实验(`tools/diag_transparency.py`)把同一个 CC 精灵按四种
  画法画在真实地形上:
  - A 无阴影 → 不透明
  - B 阴影在精灵**下**(当前代码) → 不透明
  - C 阴影盖在精灵**上** → 不透明
  - **D 精灵 alpha=130 → 半透明,与真机截图一致**

### 1.2 真正的根因

```java
// GameView.drawEnt()
p.setColor(Color.argb(90, 0, 0, 0));   // ← Android 的 setColor 会连同 alpha 一起设成 90
c.drawOval(...);                        //    阴影本身正常(35% 黑)
c.drawBitmap(s.sheet, src, dst, p);     // ← drawBitmap 会拿 Paint 的 alpha 去乘
                                        //    精灵自己的 alpha → 只剩 35% 不透明度
```

Android 语义:`Paint.setColor(int)` 设置的是 **ARGB 整体**,alpha 通道一并被改;
`Canvas.drawBitmap(..., Paint)` 会用 Paint 的 alpha 调制位图的 alpha。
于是"画阴影 → 画自己"这个顺序让每个单位/建筑都被画成半透明。

### 1.3 证据链(与截图逐条吻合)

| 截图现象 | 解释 |
|---|---|
| 水晶矿**不**透明 | 矿物在阴影之前绘制,`p` 的 alpha 尚未被污染 |
| 单位 + 建筑**全**透明 | 每个实体都"先画阴影 → 再画自己" |
| 选中绿圈、血条是亮的 | 它们用 `Color.rgb(...)`(alpha=255)上色,顺带把 alpha 复位 |
| 飞龙最透 | 飞行单位阴影用 `argb(45,…)` → 只剩 18% 不透明度 |
| v2.3 没这个问题 | v2.3 还没有阴影椭圆(批次五 #17 才加的) |

### 1.4 修复方案

- **画完阴影立刻 `p.setAlpha(255)`**(两个分支各一行),或阴影改用独立 Paint。
- 顺带修正:**建筑不该有地面阴影**。现在 4 格建筑的椭圆按
  `Math.max(radius, tiles*14)` 取值,比精灵本身还宽,看起来像一滩黑水;
  且阴影画在精灵下面、被精灵的透明区域透出来,加重了"糊了一层"的观感。
  → 建筑改为**不画阴影**(最多保留一条贴地窄暗边),单位保留椭圆。

### 1.5 同类隐患排查(本轮一并核对)

| 位置 | 是否泄漏 | 结论 |
|---|---|---|
| `drawEnt` 阴影(argb 90/45) | **是** | 唯一泄漏点,即本 Bug |
| 尸体淡出 `setAlpha(255*a)` → `setAlpha(255)` | 否 | 成对 |
| 建造虚影 `setAlpha(150/110)` → `setAlpha(255)` | 否 | 成对 |
| 命令卡置灰 `setAlpha(90)` → `setAlpha(255)` | 否 | 成对 |
| 小地图迷雾 `setAlpha(150)`(画到 fogPaint) | 否 | 用的是独立 Paint 且成对 |
| `drawConstruction` 火花 `argb(230,…)` | 否 | 只影响随后的圆点,属预期 |
| 防御性加固 | — | `render()` 开头统一 `p.setAlpha(255); p.setStyle(FILL)`,游戏线程吞异常时 Paint 状态也不会跨帧泄漏 |

## 二、九宫格命令卡放大

### 2.1 现状

`GameView`: `CELL_DP=44`(保底 40)、`CARD_GAP_DP=5`、`CARD_PAD_DP=16`、
`CONSOLE_MAX_FRACTION=0.46`。

### 2.2 方案:压缩内边距换格子尺寸

不加高面板也能放大——把"面板内留白"让给格子:

| 参数 | 旧 | 新 |
|---|---|---|
| `CELL_DP` | 44 | **50** |
| `CELL_MIN_DP` | 40 | **46** |
| `CARD_GAP_DP` | 5 | **4** |
| `CARD_PAD_DP` | 16 | **10** |
| `CONSOLE_MAX_FRACTION` | 0.46 | **0.50** |

### 2.3 数字权衡(必须如实呈现)

| 机型 | 格子 | console 占屏高 | 播放区占屏高 |
|---|---|---|---|
| 2400×1080 @2x | 88px→**100px**(+14%) | 31%(不变) | 54%(不变) |
| 1920×1080 @2x | 88→**100** | 31% | 54% |
| **1280×720 @2x(最紧)** | 88→**100** | 44%→**47%** | 45%→**42%** |
| 1280×720 @1x | 44→**50** | 46%→**47%** | 72%→**72%** |
| 800×480 @1x | 44→**50** | 55%→**56%** | 59%→**58%** |

代价:最紧机型播放区 **-3 个百分点**;收益:格子 **+14%**,而且为第 2.3 项的
中文标签腾出了空间。

### 2.4 验收

`HudPreview.java` 六种分辨率回归:**重叠 / 出屏 / 面板过大 = 0**,且
播放区 ≥ 40% 才放行。

## 三、命令卡加中文

### 3.1 布局

- 每格**底部加一条半透明黑条**(高约 11dp),写中文;用已有的
  `drawOutlined`(黑描边)保证压在图标上仍可读。
- **造价角标并入同一条**:左侧中文名、右侧矿/气数字(瓦斯用 `150+75` 形式),
  不再单独占一条;负担不起时整条数字变红。
- 文案表(与 `Game.Type.name` / 动作一一对应):

| 动作 | 中文 |
|---|---|
| attack / stop / siege / unsiege / rally | 攻击 / 停止 / 架塔 / 解除 / 集结 |
| build:cc / depot / barracks / refinery / factory / turret | 基地 / 补给 / 兵营 / 炼油 / 重工 / 炮塔 |
| train:scv / marine / firebat / vulture / tank | SCV / 机枪兵 / 喷火兵 / 雷车 / 攻城坦克 |

### 3.2 生产队列

队列竖列的小图标同样在下方加名字;取消退款交互不变。

## 四、中间信息面板:透明化 + 收缩

### 4.1 背景

`drawConsolePanel` 里信息面板用 `bevelPanel`(不透明)整块填充,用户觉得
占地方、挡地图。

### 4.2 方案

1. **背景半透明**:新增 `bevelPanelTranslucent`,填充改约 55% 不透明度的
   深色(`argb ≈ (150, 16, 20, 32)`)+ 保留 1px 亮边;地图能透出来。
   文字全部已有黑描边,可读性不受影响;必要时把 HP 条底衬加深。
2. **未选中时整块收起**:去掉"星 际 争 霸"装饰 logo,面板区域只剩
   编队 1/2/3 三个槽(浮在小地图右侧),把空间还给地图。
3. **选中单个单位时宽度按内容自适应**:名字 + 官方英文名 + HP 条 +
   状态行所需的宽度,不再撑满中间整条;多选(出现兵种分格)时再撑满。

### 4.3 命中区域

信息面板从"命中即空白"改为:未选中时该区域**完全交给地图**
(点那儿就是选兵/下令),这一点要和触控命中测试一起改,避免出现
"看得见地图却点不到"的死区。
