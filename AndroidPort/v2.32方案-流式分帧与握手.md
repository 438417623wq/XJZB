# v2.32 方案:流式分帧 + 开局握手(无头)

> 前置状态:v2.31 已出包(100 项断言 PASS,两台机器在乱序链路上逐回合全等)。
> v2.31 的 `Link.send(String)` 假设**消息边界被保留**——这在进程内是真的,
> 在**真实 TCP 上不是**。TCP 是字节流:一次 `send` 可能被拆成两个包,
> 两次 `send` 可能被合成一个包。本期补上这一层,并把它测出来。

---

## 本期要证明的两句话

1. **分帧**:一串字节无论被切成什么样子喂进来,出来的**行序列必须完全一样**;
2. **握手**:两台机器开局前交换(地图/族/难度/人数/版本/种子),
   不一致就**拒绝开局并说明原因**,而不是连上之后各跑各的。

这两条都不需要设备,`GameDesktop` 里就能跑。

---

## 批次A:`core/LockstepStream.java`

TCP 是字节流,所以线上必须自带边界。选择**行分帧**
(`\n` 结尾的 UTF-8 文本),理由:

- 指令行本身是文本且**不含换行**(见 `commandFor` 的格式),不用转义;
- 抓包/日志肉眼可读,和回放文件是同一套写法;
- 半包/粘包是接收侧缓冲区的问题,不是协议的问题——收满一行才交付。

`feed(byte[] buf, int len)` 把字节喂进累积缓冲,`lines()` 取走
**已完整**的行;`encode(String)` 把一行变成"行 + \n"的字节。

---

## 批次B:`core/Handshake.java`

开局前主机广播自己的开局参数,客机核对。任何一项不一致就拒绝:

| 字段 | 不一致的后果 |
|---|---|
| `version` | 两边的模拟可能不同 → 必拒 |
| `map` | 两张不同的图 → 必拒 |
| `players` | 回合门禁的 N 不同 → 必拒 |
| `seed` | AI 的随机序列不同 → 必拒 |
| `race` / `difficulty` | 记录用,不一致仅提示(不拒) |

拒绝要**说明是哪一项**,否则玩家只会看到"连不上"。

---

## 批次C:`[v232]` 断言

1. **分帧与切法无关**:把同一串消息按 1 字节、3 字节、7 字节、
   整块、以及**跨多字节 UTF-8 字符**的切法喂进去,出来的行序列全等;
2. **粘包**:两条消息合成一次 `feed`,出来两行;
3. **半包**:一行拆成多次 `feed`,在补齐之前 `lines()` 为空;
4. **CRLF 容错**:行尾带 `\r` 也认(某些栈会带);
5. **握手放行**:六项全同 → `accept` 返回 null;
6. **握手逐项拒绝**:version / map / players / seed 各改一项,
   都必须被拒**且原因里点名那一项**;
7. **race/difficulty 不同只提示不拒**;
8. **端到端**:把 `Lockstep` 的一整回合用 `LockstepStream` 分帧
   (按 3 字节切)喂给对面,对面解出来的命令与直接投递**完全一致**。
