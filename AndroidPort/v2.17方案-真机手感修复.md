# v2.17 方案:真机手感修复(点选/黑边/续建/血条)

> 前置状态:v2.16 已出包(39 图入库 + 回放录制层)。本方案四个问题全部
> 来自 v2.16 真机试玩反馈,共同点是**桌面验证台发现不了**——都是手感/
> 渲染类,与 v2.15 内存危机同一教训:修完必须真机逐项过。

## 问题一:点单位点空 → 误发移动命令(P0)

### 现象与根因

- `GameView.unitAt`(GameView.java:3863)命中半径 =
  `max(radius, tiles*14) + 6` **世界像素**:SCV/机枪兵 radius=9 → 命中
  半径 15 世界像素,0.7 视野下只有 **~10 屏幕像素**;手指点选误差普遍
  15–30 屏幕像素,小单位几乎必点空。
- 点空 + 当前有选中部队 = `doTap` 落到底部 ground 分支**立刻
  `orderMove`**(GameView.java:3840-3857)——"点一下没点上,全军走散"。
- 建筑用圆形近似(tiles*14):4 格指挥中心命中半径 56,真实半对角 90,
  贴角点击也落空。

### 修法(两段式命中)

1. `unitAt` 改两段:先按现有精确半径查;落空再按 **dp(20)/zoom 的屏幕
   保底半径**查一遍,取中心最近者。扎堆时最近中心优先,不会乱认人。
   保底数值真机调,不进 Settings。
2. 建筑命中改**矩形**(footprint tiles*32 边界 + 少量外扩),圆半径保留
   作为非建筑单位的名义半径。
3. 落空且无选中 → 维持现状(清除选择);落空但有选中 → 仍是移动
   (SC 语义不动摇),靠 1/2 把"落空"本身消灭掉。
4. 顺带(可选,一句话工作量):敌人可点选条件从 fog!=0 收紧到 fog==2,
   探索过但当前黑视里的敌人不再能凭空点中攻击。

### 验收

- GameDesktop 新增 `[pick]` 段:SCV/小狗/机枪兵在 zoom 0.7/1.0/2.0 下
  保底命中半径换算正确;4 格建筑四角 8 世界像素内必命中;
- 真机:0.7 视野连点 10 次小狗 ≥9 次命中(此前约一半);点空不再走散。

## 问题二:滑动视野大黑边(P0)

### 现象与根因(两个独立来源,都要修)

1. **钳制与锚点不一致**(GameView.java:640-668):`sy()` 把 camY 锚在
   屏幕几何中心 H/2,而钳制半高按 `(H-顶栏-底台)/2` 算——游戏区实际
   中心比 H/2 高 (底台-顶栏)/2 ≈ **55dp**。推到地图上沿时,顶栏下方
   露出 ~(底台-顶栏)/2 的死黑带(0.7 视野下约占游戏区高度三成);
   地图下沿最后 55dp 则永远藏在底台后面够不着。此黑带是**常驻**的,
   与 zoom 无关,一推到上沿就有。
2. **地形块懒解码跳过**(GameView.java:525-534、678-683):LRU 上限
   24 块;256×256 图 256 块,快速滑动持续换入换出。首访问是渲染线程上
   同步解码(10–30ms,追手时掉帧);解码失败时(BitmapFactory 吞 OOM
   返 null——v2.15 同款陷阱)`chunk()` 返 null,render 直接 continue,
   **一整块 512×512 死黑**。

### 修法

1. **锚点修正(一行级)**:`sy()/wy()` 锚点从 H/2 改为游戏区中心
   `hud + (H-hud-bottomH)/2`。代入后现有 camX/camY 钳制公式对上下沿
   **精确成立**(sy(0)=顶栏底、sy(hPx)=底台顶),不用另写不对称钳制。
   所有世界渲染都走 sx/sy 自动一致;minimap 视口框自算,天然对齐。
2. **地形块异步化**:
   - 解码改后台线程,就绪后加锁入缓存;渲染线程只查表;
   - miss 帧不再跳过:画该块的 minimap 放大占位(低清但**永不死黑**);
   - LRU 上限按设备 memoryClass 分档(≥256 → 48 块,否则 24);
   - 地形块试 RGB_565 解码(地形不透明,先桌面并排对照再全量,
     内存减半,48 块也只要 12MB);
   - 视口外扩 1 圈后台预取,滑动追手。
3. GameDesktop 新增 `[camera]` 段:对 96/128/256 三种图,把 camY 推到
   上下极限,断言 sy(0) ≤ 顶栏 且 sy(hPx) ≥ H-底台(上下沿不露底)。

### 验收

- 真机:0.7 视野推到任意图四角四沿,录屏无死黑带、无死黑块;
- 桌面 `[camera]` 全绿;低端机(memoryClass 小)LRU 分档生效。

## 问题三:工人一走,建造卡死(P0)

### 现象与根因

- 进度只在"工人贴着目标建筑"时增长(距离 < tiles*16+24,
  Game.java:2925-2946);`orderMove` 清 `e.target`(Game.java:1764)
  → 进度冻结在当前百分比。
- **没有续建入口**:选中工人再点自家未完成建筑,doTap 走"选中建筑"
  分支(GameView.java:3812),不下建造单;未完成建筑的命令卡也没有
  续建项。矿已扣,建筑只能烂尾。
- 三族共用这套"工人拴绳"模型,而原版星灵/虫族放下即自建——玩家按
  P/Z 直觉把工人调走,正好踩中。

### 修法(两层)

1. **续建指令(保底,必须)**:选中工人 + 点击自家 constructing 建筑 =
   下"继续建造"(orderResumeBuild:target=b、workerState=W_IDLE);
   人族维持拴绳+可续建(原版 SCV 语义)。未完成建筑的信息面板已有
   "建造中 x%"(GameView.java:1984),命令卡补一行提示
   "派工人点击此建筑继续"教会玩家。
2. **星灵/虫族放下即自建(对齐原版,同批)**:P/Z 建筑 spawn 后
   buildProgress 按 dt/buildTime 自走(挂进 updateProduction 现成循环);
   探测机/工蜂放下后即刻自由。虫族原版"吞"工蜂——本作工人不消失,
   保持 v2.8 以来的简化,立此存照。人族不自动建。
3. 边界:人族半途工人死亡 → 任意工人可续建(1 已覆盖);存读档字段
   (buildProgress/constructing)不动。
4. GameDesktop 新增 `[build]` 段:星灵枢纽放下后工人调走进度照涨到 1;
   人族兵营工人调走进度冻结、下续建单后涨到 1;全程矿物账对得上。

### 验收

- 真机:星灵/虫族放下建筑立刻拖工人去开矿,建筑自己长完;
  人族 SCV 被拉走后,选中别的工人点半截兵营能续建;
- 桌面 `[build]` 全绿。

## 问题四:战场血条看不清(P1)

### 现状与不足(GameView.java:834-854)

- 高度固定 4\*zoom 屏幕像素:0.7 视野下 ≈3px,几乎不可见;
- 宽度 `r*1.9` **无下限**(对比:建造进度条有 max(18\*zoom,…) 下限,
  GameView.java:1097)——小狗血条只有 ~10px;
- 只在掉血后出现(SC 惯例本身没错),但配合上面两条,交战时读不出
  谁在掉血;神族护盾条又叠在上面更密。
- 信息面板血条数字画在条右侧(tx+barW+6),窄屏按面板宽收 barW 时
  数字会溢出面板右缘。

### 修法

1. 血条/护盾条加**屏幕像素下限**:高 max(4\*zoom, 3dp)、宽
   max(r\*1.9, 16dp);间距与描边不动;
2. Settings 加**"始终显示血条"开关**(默认关;开了满血也画,敌我同
   规则)——Settings.java 一个 boolean,持久化现成;
3. 面板数字改画在条内右对齐(或条下),窄屏不再溢出;
4. HudPreview 加一帧:满血/掉血/掉盾三个单位 × zoom 0.7 与 2.0 并排,
   肉眼验收下限生效。

### 验收

- HudPreview 并排图 0.7 视野下血条清晰可读;
- 开关即时生效、重启保持;人/虫控制台像素不变。
