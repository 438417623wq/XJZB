# v2.34 方案:断线判负(超时弃权)

> 前置状态:v2.33 已出包(102 项断言 PASS,发现 + 大厅)。
> v2.31 的"等慢机"有一个**必须补上的反面**:对面**永远**不来怎么办?
> 现在两台机器会一起无限卡住——这在真机上就是"死机"。
> 本期给出可判定的规则,并把它测出来。

---

## 规则

1. 每次 `Game.update()` 发现回合未齐,`Lockstep.stallTurns++`;
   齐了则清零。这是"这一回合等了多久"的**帧数**,不是墙钟——
   桌面断言才能确定性地推进它;
2. `stalledPlayer()` 说出**是谁没上报**(多个时取最小的),这样
   提示能点名,而不是只说"网络不好";
3. `stalledOut(limit)`:`stallTurns >= limit` 即为"对面已经没了";
4. `forfeit(player)`:**只能判一次**;记下输家与赢家;
5. 判负之后 `ready()` **不再等这个人**(他此后按空心跳计),
   于是对局可以正常收尾、正常出结算画面,而不是僵在那里;
6. **限额之前回来的人不算掉线**:`stallTurns` 一清零,什么都没发生。

限额取多少?30Hz 下 `STALL_LIMIT = 300` 帧 = **10 秒**。
低于 10 秒会把"对面正在切后台/抖一下"误判成掉线;
高于 10 秒玩家会以为游戏死了。真机偏离再单列调参,不改结构。

## 批次A:`Lockstep` 增补

```java
public static final int STALL_LIMIT = 300;   // 10 s at 30 Hz
public int stallTurns;                        // 连续未齐的帧数
public int forfeitLoser = -1;
public int forfeitWinner = -1;

public void noteStall();                      // Game.update 未齐时调用
public int stalledPlayer();                   // -1 = 无人缺
public boolean stalledOut(int limit);
public boolean forfeit(int player);           // 只能成功一次
public boolean isDropped(int player);
```

## 批次C:`[v234]` 断言

1. `stallTurns` 在未齐时递增、齐了立刻清零;
2. `stalledPlayer()` 点名正确的玩家;全员齐时报 -1;
3. `stalledOut` 在限额那一刻为真,限额前一帧为假;
4. `forfeit` 只能成功一次,且记下输家/赢家;
5. 判负后 `ready()` 不再等那个人(对局可以收尾);
6. **限额内回来的不算掉线**:中途齐了一次,`stallTurns` 归零,
   再等也不会"累计"到掉线;
7. **真跑一遍**:两个 `LockstepPeer`,一方在 t=60 帧后彻底静默,
   跑满 12 秒:断言另一端在限额处判定对方弃权,并且**在此之前的
   每一帧两边都还是同步的**(没有因为要判负就提前发散)。
