# v2.39 方案:房主真的能开局

> 前置状态:v2.37/v2.38 已把 socket 壳与断线判负接好。

---

## 本期要修的 bug

把**真实的开房/加入流程**从头走一遍才发现:**开始按钮永远点不亮**。

- `LanHost` 把房主放进 0 号座位,但**从没把它标成"已准备"**;
- 客机那边只填了**自己**一个座位。

于是房主看到 "1/2,房主未准备",客机看到 "1/2",两边
`canStart()` **永远是 false**。而**之前所有断言都是通过的**:
它们都手动把座位填好并置为准备——只有把真实流程走完才会暴露。

---

## 修法(规则放进 core,便于断言)

- `Lobby.hostSeat(name)`:**房主占 0 号位并默认已准备**——按下
  "开房"就是确认,没有别的东西要它再点一次;否则房主自己的名单
  是 "1/2,未准备",而**房主正是唯一能开局的那个人**;
- `Lobby.joinAsGuest(host, self)`:**客机的本地视图**是 2/2——
  它确知两件事:房主连着(刚握完手)、自己已准备。只填自己那一个
  座位,客机这边就还是 "1/2",理由和房主那边一模一样。

---

## 断言([v239],3 条)

1. 开房后房主在 0 号位**且已准备**;单独一人时仍 `canStart()==false`
   (单人不成局);
2. 客机的本地视图是 2/2 且 `canStart()==true`;
3. **端到端真 socket**:房主侧 2/2 且**只差客机确认**
   (`blockedReason()` 点名"未准备"),客机确认后**两边都能开局**。
